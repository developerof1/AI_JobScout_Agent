Neither tab has a canonical-criteria layer — a named location or department id that gets translated outward into each source's own query shape, and validated inward against each source's own returned text. Healthcare IT's 2 locations × 5 departments, read differently by Built In Chicago and digital-health-jobs.com, need exactly that layer built new.

What this means for the Healthcare IT tab

Against Figure 1 and Figure 2 — what already exists to stand on, and what doesn't.

Reuse as-is

  • Server-rendered HTML + page=N pagination engine scrapers/methods/html_pages.py — both candidate sites fit this shape
  • Registry dispatch, zero driver changes to add a source SOURCE_REGISTRY pattern from scrapers/source_registry.py
  • Generalized tab tracking helper, one new TAB_CONFIGS entry getTrackedIds(tab,action)/saveTrackedIds(...) in dashboard/app.js
  • Reusable workflow_call template — a new tab is a ~10-line caller workflow .github/workflows/_tab_scout_template.yml, not a new 5-step file
  • FilterEngine's dimension registry — the class itself, not just the idea add one _dim_department() matcher, register it in DIMENSIONS

New — doesn't exist yet

  • Canonical criteria config 2 locations × 5 departments, shared across sources
  • Per-source outbound map canonical id → query param / URL template — no source does this today, all hardcode their query
  • Department as an inbound filter dimension utils/filter_engine.py only knows location, title, date — department is new
  • Just a new tab config — no new driver, output format, or dashboard code config/tabs/healthcare_it.json + one new scrapers/methods/*.py if no existing method fits
  • Confirmed vs. unclassified card treatment reduced-opacity rendering for a job Filter Engine can't classify on a dimension, instead of dropping it — dashboard/app.js has no hook for this yet
